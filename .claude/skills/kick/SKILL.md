# kick

指定された issue をすべて片付ける。PR は 1 本にする。

不明点があれば、どの段階でも作業を止めて user に質問する。質問には推奨する回答を
添える。コードを読めば分かることは質問しない。

## 手順

1. **読む**: issue と、関係する `docs/requirements.md`・`docs/design-*.md` の節を
   読み、受け入れ条件を issue ごとにまとめる
2. **直す**: issue ごとに、まず失敗するテストを書いてから修正する。仕様が変わる
   なら要件定義・設計書も更新する。`bun run ci` を通し、issue ごとに 1 コミットにする
3. **実機で確かめる**: `bun run build` した `dist/cli.mjs` を再現ケースに走らせる
   （AWS 認証情報が無ければ、その旨と代わりに確かめた範囲を記録する）。性能を
   変えたら、関係する `bench/` を変更前後で `bun run bench` し、差分を意図どおりか
   どうか 1 件ずつ仕分ける
4. **/wrapup** を実行する
5. **PR を出す**: 本文は英語で書き、対象の issue を閉じる。中心は、issue から
   読み取れない判断・意図・捨てた案を書くこと。実機で確かめた結果と、起票した
   残課題も載せる。diff を見れば分かることは書かない
6. **残課題を起票する**: スコープ外にしたものは、重複がないか確かめてから
   issue にする
7. **追い続ける**: 15 分ごとに issue と PR を確認し、CI を緑に保つ。レビュー指摘
   と issue の更新にも追従する。PR が merge / close されたら確認をやめる
